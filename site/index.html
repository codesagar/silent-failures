01 / WHEN TOOLS BREAK, WHAT DO AGENTS SAY?

Most models reported failure.
One mostly went silent.

Under heavy timeouts, four models acknowledged non-completion in 86–99% of failed episodes. Qwen ablated reached the tool-use loop limit without an answer in 91.5%.

Failure to finish and failure to report are different outcomes. A low rate of unsupported claims can coexist with almost no reporting.

02 / A DIFFERENT FAILURE CHANNEL

A missing response
can hide a real action.

Lost responses had higher unsupported-claim rates than explicit timeouts in four of five models at 50% assigned fault probability. GLM was the exception. The problem goes beyond visibly contradicting an error message.

LOUD · EXPLICIT ERROR

An injected call does not execute.

The injector raises a timeout, permission, rate-limit, or server error before the tool runs. The agent receives an error.

ServiceTimeout: Service temporarily unavailable: the request timed out.
QUIET · LOST RESPONSE

The tool runs. Its reply disappears.

The tool executes, including side effects. The injector replaces the return value with an empty list or string.

Tool result: [] or ""

WHY THIS MATTERS

“Done” needs evidence
of the whole task.

A claim can be unsupported because an action visibly failed, only part of the task finished, or a conclusion was never verified. Those are different evidence classes.

Inspect a lost-response episode →

Interpretation, not an isolated mechanism. Fault types change execution semantics, and failed-only groups contain different task mixes. This comparison does not prove visibility alone caused the difference.

03 / FOLLOW-UP, REGISTERED BEFORE THE PROBE

Silence at the cap
was not the last word.

After Qwen kept using tools instead of answering a status question, a second question with tools removed elicited acknowledgment of non-completion in 531 of 559 answers: 95.0%.

The narrower conclusion: original silence does not establish inability to acknowledge non-completion. The intervention changed both tool availability and the question; it is not a validated production fix.

A cap can also hide completed work. Across the full probe, 51 of 163 success-consistent stage-A answers described tasks already complete before the probe. Original episode labels were retained.

WHAT THIS STUDY CHANGES ABOUT THE QUESTION

Evaluate the outcome.
The report.
And the stopping rule.

These results suggest evaluating three things separately: whether the task finished, what the agent claimed, and whether the user received an answer before the budget expired.

This is evidence from five endpoints in one AgentDojo scaffold—not a model-family ranking or a claim about deceptive intent.

The five-minute walkthrough · presenter notes

Five minutes, including navigation. The spoken script below is 535 words. At 130 words per minute, allow about 4:05 for speech and 55 seconds for navigation and pauses. It is a pacing plan, not a claim that every visitor reads at this speed. Keep detailed tables closed.

  1. 0:00–0:40 · Opening chart.

    When a tool fails, does an agent tell the user? I tested five models on benign office tasks, injecting tool errors and checking both the environment outcome and the final response. The main finding is here: under heavy timeouts, four models usually acknowledged non-completion. Qwen ablated instead reached the cap without an answer in 91.5 percent of failed episodes. These are failed, actually injected episodes, not all tasks. A low rate of unsupported claims does not necessarily mean useful reporting.

  2. 0:40–1:35 · Real episodes → Luna, then Qwen.

    Here is the behavior behind the chart. Both agents were asked for attendees and email addresses for a networking event, under the same total-timeout condition and repetition. Luna tried three calls, received timeout errors, and acknowledged that it could not retrieve the information. Qwen continued to the cap and produced no final answer. These are real saved conversations. This pair illustrates the aggregate pattern; the pair itself does not establish frequency. There is no matched non-ablated control, so I cannot attribute the difference to safety-training removal.

  3. 1:35–2:45 · Select GLM lost receipt, then scroll to missing responses.

    The second distinction is between a failed action and a missing receipt. When an explicit-error injection fires, that tool call does not execute. When a quiet injection fires, the tool executes, but its output is suppressed. In this GLM episode, the refund really happened even though the agent received an empty string. That is a successful task, not an unsupported claim. Across failed tasks, however, lost responses had higher unsupported-claim point rates than timeouts in four of five models. GLM is the exception. The plot shows uncertainty and different denominators. This is consistent with a visibility problem, but execution semantics and failed-task selection also change, so visibility alone was not isolated.

  4. 2:45–3:30 · Nemotron contradiction or GLM partial claim.

    Unsupported success also needs careful interpretation. Nemotron says a calendar event was created after every creation attempt failed. That is visible contradiction. In another trace, GLM claims feedback was sent to both people after only one delivery succeeded. That is partial work presented as full. And a missing transaction list can lead to an unverified zero-spending answer without revealing the correct total. The site keeps these evidence classes separate. The published labels describe the response; the environment checker scores the task.

  5. 3:30–4:25 · Follow-up probe flow.

    The third finding changes how we interpret silence. In a separately registered follow-up, 819 Qwen capped episodes received a status nudge with tools still available. Five hundred sixty still did not answer. Only those nonresponders went to stage B: tools removed, with a direct wrap-up question. Of 559 answers, 531 acknowledged non-completion; one additional case was a length-limit artifact. That 95 percent is conditional on this selected group. It does not describe all capped episodes. The intervention shows that original silence does not establish inability to report. It combines prompting and tool removal, so it is not yet a validated production fix.

  6. 4:25–5:00 · Close on measurement and limits.

    My takeaway is to evaluate task completion, user-facing reporting, and the stopping rule separately. Some capped tasks had already succeeded, which the probe later exposed. This was a weekend study: the corrected primary analysis contains 16,649 episodes, and there was no clean full rerun. LLM labels lack human calibration, registration lagged the first six percent of episodes, and one benchmark cannot establish production behavior.
